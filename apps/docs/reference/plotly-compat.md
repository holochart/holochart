# Plotly compatibility

Holochart reads Plotly figures. This page says how much of plotly.js it covers, in two parts:

- **[Coverage](#coverage)**: tables of trace types, attributes, layout keys and config options,
  generated by comparing the two libraries' attribute schemas.
- **[Known deviations](#known-deviations)**: where Holochart has the attribute but draws or
  behaves differently.

To move an existing chart over, start with [Coming from Plotly](/getting-started/from-plotly).

## Coverage

The tables compare plotly.js' `plot-schema.json` with Holochart's own
([`plot-schema.json`](/reference/#plot-schema-json)), attribute by attribute. An attribute is
named by its path, such as `marker.line.width` or `annotations[].text`, and is:

- **Supported** when Holochart has the same path and accepts every value Plotly does;
- **Partial** when Holochart has the path but accepts less (fewer enumeration values or flags,
  one value where Plotly also takes an array), or accepts the attribute without acting on it;
- **Missing** when Holochart doesn't have the path. A missing attribute in a figure is ignored
  with a console warning.

This is a comparison of what the two libraries accept, not of what they draw. An attribute that
is supported here can still behave differently; those cases are under
[Known deviations](#known-deviations). Attributes that only Holochart has are not listed; they
are in the [attribute reference](/reference/).

A trace type or a layout key counts as supported only when every one of its Plotly attributes is, and as partial when Holochart has it but lacks or limits some of its attributes.

Holochart also has a trace type that plotly.js does not: [`bar3d`](/reference/bar3d).

## Known deviations

Holochart follows plotly.js' behavior unless there is a reason not to. These are the places
where it differs on purpose, or where a Plotly behavior is not implemented yet. Each chart page
has the full list for its trace type under "Plotly migration notes"; the main ones are collected
here.

### API and events

- The functional API takes an `HTMLElement`, not an element id, and resolves to a `Chart`
  object instead of the element. Figure data and events are on the chart (`chart.data`,
  `chart.on`), not on the element. See
  [Coming from Plotly](/getting-started/from-plotly#the-same-chart-side-by-side).
- `unhover` carries an empty `points` list. Plotly sends the points that were hovered.
- `plotly_autosize`, `plotly_react`, `plotly_update`, `plotly_beforeexport`,
  `plotly_afterexport`, `plotly_exportfail` and `plotly_framework` are not emitted. `resize`
  takes the place of `plotly_autosize`.
- A `click` listener that returns `false` cancels a sunburst, treemap or icicle drill-down. The
  drill-down is a `restyle` of `level` and emits `restyle`; Plotly animates it with `animate`.
- A `parcoords` brush also writes the new `constraintrange` into the figure; Plotly only emits
  the event. A `parcoords` axis drop and a `table` column drag emit `restyle` only when the
  order changed.
- Selection events of polar subplots have no `range` or `lassoPoints`, and a histogram's lists
  one point per selected sample where Plotly lists one per bin.
- `toImage` and `downloadImage` make PNG, JPEG and WebP images. There is no SVG export. Sliders,
  update menus and the modebar are page elements and are not in the image.
- Promises of interrupted animations settle, rejecting with an `Error` named
  `AnimationInterrupted`. Plotly's may never settle, or reject with `undefined`. See
  [Transitions](/fundamentals/transitions-animation#differences-from-plotly).

### Dates and text

- A JavaScript `Date` is shown at its UTC time. Plotly shows it at the browser's local time.
  Date strings without a UTC offset are read alike, without a time zone; Holochart converts a
  string with an offset (`Z`, `+01:00`) to UTC. There is no `layout.timezone`, and no
  non-Gregorian calendar (`xcalendar`, `layout.calendar`).
- Text is drawn from font files. A `font.family` that isn't
  [registered](/fundamentals/styling-themes#web-fonts) is drawn with the built-in font, TeX Gyre
  Heros, on every platform, where Plotly uses the fonts installed on the computer.
- LaTeX (`$…$`) is not rendered. Unknown tags in text are shown literally. In titles,
  annotations, legends and axis labels a newline breaks the line, where Plotly shows a space.
  See [Text](/fundamentals/hover-text-templates#differences-from-plotly).
- In the default `en-US` locale, `%x`, `%X` and `%c` follow d3's US English (`3/5/2024`,
  `12:30:00 PM`); Plotly writes `03/05/2024` and `12:30:00`. See
  [Locales](/fundamentals/locales#plotly-differences).

### Look

- Figures without `layout.template` get Holochart's dark default look, not Plotly's.
  `template: 'plotly-classic'` gives Plotly's. See
  [Default look](/getting-started/from-plotly#default-look).
- Default colorscales come from the template too: a figure that relied on Plotly's default
  `RdBu` or Viridis gets the template's scale unless it sets `colorscale`.

### Layout and interaction

- Shapes and images `above` the traces are drawn below axis lines, tick labels, the legend and
  annotations; Plotly draws them over axis lines and tick labels. See
  [Shapes](/fundamentals/shapes-images#differences-from-plotly).
- Value-based `categoryorder` sorts `median` numerically (Plotly compares strings), and has no
  `'geometric mean …'` orders.
- `xperiod` and `yperiod` alignment also works on linear axes; in Plotly it applies to date axes
  only.
- On axes with `rangebreaks`, OHLC bars, candles and heatmap cells next to a break keep their
  full width; Plotly narrows them.
- Pinch zoom works on cartesian subplots, and a vertical swipe scrolls the page in zoom mode.
  See [Interaction](/fundamentals/interaction-events#differences-from-plotly).
- Sliders and update menus are DOM controls with keyboard support; their labels are plain text
  without Plotly's markup. See [Controls](/fundamentals/controls#differences-from-plotly).
- Transitions animate every trace type and follow autoranged axes while they move. See
  [Transitions](/fundamentals/transitions-animation#differences-from-plotly).

### 3D scenes

- Tick labels and axis titles face the camera; Plotly draws them along the axes.
- A double-click resets the camera.
- Hover picks on the GPU and respects depth: you hover what you see.
- Holochart doesn't write the computed `aspectratio` and `aspectmode` back into the input
  layout.
- Camera changes in `react` and in animation frames animate.
- See [3D scenes](/fundamentals/3d-scenes#plotly-compatibility) for the rest.

### Deviations by trace type

The main deviations of each trace type, with a link to its full migration notes.

- **`scatter`**: `scattergl` is `scatter`. `line.simplify` decimates per pixel column and re-runs on zoom. A `'tonext…'` fill keeps the trace order instead of moving the trace down. No `marker.gradient`, `marker.angleref`, `marker.standoff`, `line.backoff` or `scattermode: 'group'`. Notes: [scatter](/charts/basic/scatter#plotly-migration-notes), [lines](/charts/basic/line#plotly-migration-notes), [areas](/charts/basic/area#plotly-migration-notes).
- **`bar`**: No `marker.pattern.path`. Default pattern colors are computed when drawing, so they are not in `fullData` (see [patterns](/customization/markers-patterns#differences-from-plotly)). Notes: [bar](/charts/basic/bar#plotly-migration-notes).
- **`pie`**: Hiding a slice re-flows the others without a transition. Outside labels don't push the margins. Notes: [pie](/charts/basic/pie#plotly-migration-notes).
- **`table`**: Rows are virtualized. Cells of a wrapped row share one baseline. `columnorder` in `fullData` is normalized to display ranks. Notes: [table](/charts/basic/table#plotly-migration-notes).
- **`histogram`**: Restyling one member of a `bingroup` re-bins that trace only, until the next full recalculation. No `xbins.adaptive`. Notes: [histogram](/charts/statistical/histogram#plotly-migration-notes).
- **`histogram2d`**: A click point's `pointNumber` is a flat cell index, not `[row, col]`. Notes: [histogram2d](/charts/statistical/histogram2d#plotly-migration-notes).
- **`box`, `violin`**: No `xperiod` / `yperiod`. Violin scale groups are shared within a subplot, not across the figure, and the outline is not spline-smoothed. Notes: [box](/charts/statistical/box#plotly-migration-notes), [violin](/charts/statistical/violin#plotly-migration-notes).
- **`splom`**: Default hover labels read `label: value` for both dimensions; Plotly shows `(x, y)`. Notes: [splom](/charts/statistical/splom#plotly-migration-notes).
- **`parcoords`**: Unselected lines are drawn in the same pass as selected ones. Lines are 1 px wide. No `line.coloraxis`. Notes: [parcoords](/charts/statistical/parallel-coordinates#plotly-migration-notes).
- **`parcats`**: A trace-level `hovertemplate` also applies to paths. Clicking a category band emits no `click`. Notes: [parcats](/charts/statistical/parallel-categories#plotly-migration-notes).
- **`heatmap`, `image`**: `zsmooth: 'fast'` is bilinear filtering on the GPU. Heatmap grids over 4096 × 4096 cells are not drawn. Notes: [heatmap](/charts/scientific/heatmap#plotly-migration-notes), [image](/charts/scientific/image#plotly-migration-notes).
- **`contour`, `histogram2dcontour`**: A value exactly on a level counts as above it (Plotly: below). Contour smoothing runs in grid space, so smoothed lines differ slightly. Notes: [contour](/charts/scientific/contour#plotly-migration-notes), [histogram2dcontour](/charts/statistical/histogram2d-contour#plotly-migration-notes).
- **`scatterpolar`, `barpolar`**: `scatterpolargl` is `scatterpolar`. `thetaunit: 'gradians'` converts gradians; plotly.js reads them as radians. Notes: [scatterpolar](/charts/scientific/polar#plotly-migration-notes), [barpolar](/charts/scientific/barpolar#plotly-migration-notes).
- **`candlestick`, `ohlc`**: In `boxmode: 'group'`, candles group with candlesticks only, not with boxes. `%{change}` and `%{changepercent}` are added to `hovertemplate`. Notes: [candlestick](/charts/financial/candlestick#plotly-migration-notes), [ohlc](/charts/financial/ohlc#plotly-migration-notes).
- **`waterfall`, `funnel`**: In `between` mode, waterfall bars are not lengthened by the connector width. A funnel's `marker.opacity` is applied, and `%{percentTotal}` is formatted as a percentage. Notes: [waterfall](/charts/financial/waterfall#plotly-migration-notes), [funnel](/charts/financial/funnel#plotly-migration-notes).
- **`indicator`**: Transitions lay the number out for every in-between value, and animate `delta.reference`. Notes: [indicator](/charts/financial/indicator#plotly-migration-notes).
- **`sunburst`, `treemap`, `icicle`**: Labels fade in at the end of a drill-down instead of moving with their sectors. Treemap and icicle labels wrap before they shrink. Notes: [sunburst](/charts/hierarchical/sunburst#plotly-migration-notes), [treemap](/charts/hierarchical/treemap#plotly-migration-notes), [icicle](/charts/hierarchical/icicle#plotly-migration-notes).
- **`sankey`**: Cyclic graphs are laid out and drawn with loops, so node placement can differ. No `node.hoverlabel` or `link.hoverlabel`. `'snap'` drags have no force simulation. Notes: [sankey](/charts/hierarchical/sankey#plotly-migration-notes).
- **`scatter3d`**: Projections are camera-facing sprites on the walls; Plotly flattens them onto the wall. The error bars' `width` is ignored. Notes: [scatter3d](/charts/3d/scatter3d#plotly-migration-notes).
- **`surface`**: The grid is drawn as given; Plotly resamples small grids for smoother shading. Contour levels don't follow the camera. Hover reports `pointNumber` as `[row, column]`. Notes: [surface](/charts/3d/surface#plotly-migration-notes).
- **`mesh3d`, `cone`**: Cone sizes and `alphahull` scale by the trace's own data span, not by the span of every trace in the scene. A mesh's `contour.width` is honored. Notes: [mesh3d](/charts/3d/mesh3d#plotly-migration-notes), [cone](/charts/3d/cone#plotly-migration-notes).
- **`streamtube`**: Tubes are integrated with Runge–Kutta (RK4) steps instead of Euler steps, so curved flow is followed accurately. Colors use each sample's own norm. Notes: [streamtube](/charts/3d/streamtube#plotly-migration-notes).
- **`isosurface`, `volume`**: The triangles are Plotly's. Hover snaps to the nearest grid point. No `contour`. Notes: [isosurface](/charts/3d/isosurface#plotly-migration-notes), [volume](/charts/3d/volume#plotly-migration-notes).

[Express](/express/#differences-from-plotly-express) lists the differences from `plotly.express`.

## How the tables are made

`pnpm --filter @mk7s/holochart-docs gen:compat` runs `apps/docs/scripts/gen-plotly-compat.ts`,
which the docs build runs too. It reads Holochart's schema as the docs build generates it from
the registered trace types and components, and a reduced copy of plotly.js'
`dist/plot-schema.json` (attribute names, value types and enumeration values; plotly.js is MIT
licensed) kept in `apps/docs/scripts/plotly-compat/`. The plotly.js version is stated at the top
of the coverage section.
